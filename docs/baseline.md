# 純量基準線（W1 完成時記錄）

> 這是純量版 GEMM 的效能基準線，之後向量版、自訂指令版都跟這裡的數字比較。
> cycle 數依據 cpu.cpp 的簡化模型（非實測），三個版本使用同一套參數。

## 指令數與 cycle（不同矩陣大小）

| N | 指令數 | cycle 數 | 每元素指令數 |
|---|-------:|--------:|----------:|
| 4  |   1,058 |   1,618 | 66.1 |
| 8  |   7,774 |  12,062 | 121.5 |
| 16 |  59,702 |  93,238 | 233.2 |
| 32 | 468,070 | 733,286 | 457.1 |

指令數隨 N 呈 O(N³) 成長（N 加倍 → 約 8 倍），符合矩陣乘法理論複雜度。

## 指令組成（N=4）

| 用途 | 佔比 |
|---|---:|
| 真正的運算（乘加） | 12.1% |
| 記憶體存取 | 13.6% |
| **算記憶體位址** | **54.4%** |
| 迴圈控制 | 19.3% |

**核心觀察**：超過一半的指令花在計算記憶體位址，真正的算術僅約 12%。
這是向量化（攤掉位址計算）與自訂指令（融合位址遞增）要攻擊的目標。
