結果:cycle 加速從膨風的 4.4x 變成誠實的 3.8x。 這個「變低」是好事——它反映了「向量指令單條比較貴」的現實。報告裡你可以這樣講:

指令數加速 4.3x,但 cycle 加速僅 3.8x,因為向量乘加(vmacc)單條成本較高。這說明單看指令數會高估效能,必須用 cycle 模型才能反映真實加速。

experiments.md 的 W5 也補一句(例如「cycle 加速從 4.4 降到 3.8,因為精修後 vmacc 單條較貴」)

所以精確地說:vlmacc.pi = vle32.v + vmacc.vx + 「位址遞增」三合一。

關鍵在誠實計價。 vlmacc.pi 記 5 cycle,不是 2。理由:

它內部還是要做「載入(3) + 乘加(4)」的實際工作,融合只省下「指令發出開銷 + 位址計算」,所以記 5(比 3+4=7 少 2,那 2 就是省下的開銷)。如果貪心記成 2,等於宣稱融合把乘加也變快了——那是造假。

自訂指令能省的永遠是「開銷」,不是「運算本身」。 乘加該做 N 次還是 N 次。這句話講得出來,代表你真的懂優化的本質。
